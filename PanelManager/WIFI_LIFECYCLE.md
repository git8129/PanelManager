# WiFi 开启与扫描恢复

## 范围与行为

本说明对应 `wwwroot/script.js` 的 WiFi 前端状态机，涵盖开启意图、扫描生命周期、连接 busy 重试凭据及连接/IP 状态显示，不改变设备协议、C# 串口桥或页面结构。

开启直接发送 `setMode(1)`，不等待前置 `getStatus`。开关意图与设备快照分别维护，旧 OFF 响应不会覆盖新的开启意图。初始化查询失败、设备正在扫描或扫描终结通知缺失时，通过有界状态查询恢复扫描调度。

连接 busy 重试期间，凭据由当前连接事务持有，避免重试发送空密码。在请求接受、失败、取消、关闭或断链时清理凭据；重试沿用最初的 35 秒事务截止时间。

关闭前保存状态快照。非成功响应恢复最后已知状态与整套 UI，避免开关、列表和状态显示不一致。明确拒绝提示失败；超时或传输异常提示关闭状态待确认，并通过短查询确认结果。

扫描会话到期不取消有效连接的恢复。连接恢复根据当前 operation 身份、自己的恢复代际和固定截止时间判断，不依赖扫描状态代际。

## 命令契约

- `setMode` 携带 `{ mode: 1 }` 且不带 SSID，表示开启并尝试已保存网络，不需要前置 `getStatus`，也不需要改用其他模式。
- `setMode` 保留操作结束后响应的语义，固件请求期限为 32 秒。因此上位机等待 35 秒，不能把它改成短时接受确认，不能因响应未到就自动重发。
- 无保存网络的 code 4 不等于射频一定关闭；busy、超时也不等于已开启。终结后读取新快照，只有状态允许时才扫描，不伪造成功。
- `startScan` 的接受响应与后续扫描终结事件分开。`stopScan` 不保证物理扫描立即取消，离页后重新进入仍必须先读取真实状态。

## 所有权与恢复

- 用户开关操作拥有独立代际。关闭、再次切换或断链使旧开关回调失效，旧开启回调不能重新开启或覆盖新操作。
- `wifiEnablePending` 保留等待中的开启意图；设备快照仍如实保存 OFF，但不能在开启等待期间据此隐藏列表或停止恢复。
- 页面扫描会话拥有查询和扫描请求代际。离页、关闭、会话到期时清理扫描定时器并使旧扫描回调失效。消息已经发送到设备后无法由前端撤销；代际只隔离其回调副作用。
- 扫描到期保留有效连接的 busy 定时器和在途查询。真正离页、关闭等清理才单独取消连接恢复并递增其恢复代际；即使迅速返回，旧连接查询也不能重试。离页不撤销设备已接受的连接，原连接事务仍按自己的截止时间终结。
- 连接 busy 恢复最多保留一个定时器或一个在途查询；重复调用不增加请求。事务接受前的凭据在终结/取消时清理，扫描到期不会提前清理。
- 初始化与扫描恢复共用单个在途状态请求和一个恢复定时器。busy 快照只触发状态查询，不重复发送扫描命令。
- scanComplete、startScan completion 与 watchdog 都通过短状态查询收尾。终结事件可能重复或迟到，不直接把当前扫描改成空闲；由新快照判断是否续扫。
- 恢复到空闲后只保留一个续扫定时器。旧 OFF 快照、丢失接受响应、缺少任一种扫描终结通知，都有有限恢复路径。
- 恢复窗口耗尽后不因重复事件续期；切回页面或新开关操作可开始新的恢复会话。180 秒会话到期只停止继续发现，不假称设备当前物理扫描已取消。页面之外仍允许单次状态读取更新首页，但不启动后台扫描。

## 参数

| 参数 | 值与边界 |
| --- | --- |
| getStatus / startScan 接受响应超时 | 2 秒；丢失接受响应后先查询，不直接重发扫描 |
| 恢复查询间隔 | 上一次查询完成后至少 1 秒；watchdog 可立即开始首查 |
| 普通恢复窗口 | 20 秒，不因重复事件延长；已发出的最后一次短查询最多再等 2 秒 |
| 开启期间恢复窗口 | 最多 35 秒；操作终结后允许重新确认最终快照 |
| setMode 响应超时 | 35 秒，沿用操作终结语义 |
| 扫描完成 watchdog | 接受响应后 16 秒，到点进入短查询恢复 |
| 续扫间隔 / 扫描请求 duration | 5 秒 / 10 秒，沿用原参数 |
| 页面扫描会话 | 180 秒，限制续扫及扫描恢复，不因通知续期，不终止有效连接恢复 |
| 连接事务 | 最初请求起 35 秒，busy 重试不延长 |

恢复阶段的查询与扫描接受请求受前端去重控制；连接 busy 的状态确认属于连接事务，额外受其固定截止时间约束。详情页等非本主题命令不纳入此恢复调度器。

## 回归入口

在仓库根目录执行：

```powershell
node --check PanelManager/wwwroot/script.js
node --check PanelManager/tests/wifi-lifecycle.test.cjs
node --test PanelManager/tests/wifi-lifecycle.test.cjs
```

测试直接读取当前工作区 `script.js` 的真实声明及函数，在 Node VM 内替换 WebSocket 请求、时钟、定时器和 DOM 渲染边界，不复制状态机实现，不访问设备，不包含真实凭据。

覆盖立即开启、OFF 竞态、快速开关、过期响应、无保存网络、初始化查询失败、busy 状态收敛、两种终结事件单独/重复/乱序、watchdog、扫描接受响应丢失、恢复期限与会话期限、密码保留/清理及固定连接期限。

还覆盖关闭拒绝/超时后查询耗尽的 UI 一致性、连接恢复跨越扫描到期、离页时取消定时器和在途查询（含迅速返回），以及重复恢复去重、连接到期停止和凭据清理。

## 连接与 IP 显示契约

连接与 IP 就绪状态按以下契约显示，自动连接与本地发起的连接使用相同映射。SSID、STA 模式或残留 IP 不单独作为连接成功的依据。

| 输入 | 显示/处理 |
| --- | --- |
| `getStatus.data.connected:true`，`ip` 为有效非零 IPv4 | 已连接（仅证明设备报告连接与 IP，不证明互联网可用） |
| `connected:true`，IP 缺失、空或 `0.0.0.0` | 等待获取 IP 地址；不完成本地连接事务 |
| `connected:false` | 不允许通过 SSID、STA 模式或残留 IP 推断已连接 |
| `connecting:true`，无上述等待 IP 证据 | 正在连接；自动连接也显示列表进度 |
| 旧响应缺少 `connected` | 仅 `on:true`、非空 `ssid`、非 connecting 且非零 IPv4 时兼容显示已连接 |
| `wifi:connected {ssid,ip,rssi?}` | IP 合格才结束事务，否则提示等待获取 IP 并有界查询 |
| `wifi:connectFailed {ssid?,reason}` | 首页、列表及提示显示失败；`reason:"DHCP timeout"` 映射为“获取 IP 地址超时”，清除本地 IP/就绪状态 |
| `wifi:dhcpSuccess {ip,netmask,gateway,dns?}` | 因无 SSID/事务标识，只触发状态确认，不直接将 IP 归给当前连接 |

`waitingForIp` 仅为前端派生字段，不是新增设备协议字段。有效 IP 判断为四段十进制 IPv4、每段不超过 255，排除 `0.0.0.0` 与 `255.255.255.255`。设备只报告 `connected:false,connecting:false,ip:"0.0.0.0"` 且没有失败事件时，现有契约无法区分未关联与 DHCP 失败；不得从 SSID 或日志外的信息猜测 WPA 完成。设备需提供正在连接状态、连接阶段证据及 `connectFailed` 终结事件，才能完整展示实际过程。

IP 映射回归覆盖显式 false 不被残留 IP/SSID 覆盖、无 IP 连接事件保持事务、DHCP 超时显示在首页，以及无归属 DHCP 事件经快照确认。

## 实机验证与限制

模拟回归覆盖前端响应时序；串口传输、设备响应和网络行为需要实机验证。

实机验证应覆盖：无保存网络开启、有保存网络但 AP 不可达、扫描中切页、快速开关、丢失扫描终结事件、busy 后连接未保存网络。核对请求 id 和发送/响应时间，确认无需切页续扫，并测量实际响应延迟是否适合 2 秒短查询。日志不得记录密码。

设备长时 busy、驱动故障、串口写超时或设备无响应会耗尽恢复窗口。上位机代际无法撤销设备已接受的旧操作，也不保证关闭请求在设备 busy 时一定成功；失败仍反馈并查询设备实际状态，不通过重复控制命令延长恢复期限。
